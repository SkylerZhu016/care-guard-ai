# 守望基层医疗 · 静态 UI Demo

这是一个与现有 `frontend/`、`backend/` 和其他服务完全分离的 Vue 3 静态界面工程。它只用于页面设计、流程验证和视觉迭代，不调用真实接口、不实现认证，也不会写入数据库。

## 现有前端分析摘要

原项目使用 Vue 3、Vite、Pinia、Vue Router、Element Plus 与 ECharts。主要页面包括：

- 登录入口：四类演示角色统一从账号密码入口进入。
- 患者端：新建预问诊、问诊记录、随访任务、健康资料。
- 医务端：审核队列、事实核对、规则与证据、随访决策。
- 随访端：任务筛选、执行与结果记录。
- 治理端：运行指标、安全告警、知识来源、Agent 轨迹与审计。

现有页面已经具备较完整的安全边界表达，但组件样式和业务状态集中在大型页面文件中，角色间信息密度接近，关键任务和辅助信息的层级区分仍有优化空间。

## 本 Demo 的设计方向

- 保留原项目的医疗绿色与“规则优先、人工终审”语义，重新统一色彩、间距、圆角和状态体系。
- 用角色启动页代替真实登录，方便设计人员快速切换四端视角。
- 把核心任务放在第一视口：患者填写、医务审核、随访执行、安全治理。
- 使用一致的侧栏、顶栏、卡片、状态标签、弹窗和分页组件。
- 桌面端强调并行信息核对；移动端改为单列、抽屉导航和可折叠表格结构。
- 所有按钮、表单、步骤、筛选、角色切换和弹窗均使用 Vue 本地状态模拟。

## 目录

```text
ui-demo/
├─ src/
│  ├─ components/       # 应用壳、状态标签、弹窗、分页和次级页面
│  ├─ views/            # 患者、医务、随访、治理四个主页面
│  ├─ mock.ts           # 集中管理的模拟数据
│  ├─ App.vue           # Demo 启动页、角色和导航状态
│  └─ styles.css        # 设计令牌、组件样式与响应式规则
├─ package.json
└─ vite.config.ts
```

## 启动

```powershell
cd ui-demo
pnpm install
pnpm dev
```

生产构建检查：

```powershell
pnpm build
```

## 当前交互范围

- 角色启动页与四类角色快速切换。
- 患者端三步预问诊、按需展开的症状选择层、事实字段、免责声明和提交弹窗。
- 医务端队列切换、事实/证据/随访标签页、人工优先级调整和终审确认。
- 随访端指标筛选、搜索、分页、任务执行和结果填写。
- 治理端指标、告警、知识来源搜索、分页与索引重建确认。
- 次级导航页使用代表性 Mock 内容验证信息架构。

## 迁移边界

设计确认前不要把本目录合并到原 `frontend/src/`。迁移阶段应先冻结设计令牌和组件 API，再逐页把 Demo 的展示组件接入原项目的 Pinia、Router 与 `ApiClient`。业务规则、权限校验、请求协议和状态机继续以原项目为准，不应从 Demo 反向覆盖。
