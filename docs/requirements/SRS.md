# 软件需求规格说明（SRS）

## 1. 产品范围

系统面向预问诊信息整理、人工审核和随访执行。患者端不输出诊断、处方、模型名称、规则代码或“低风险”结论。所有自动结果必须由医务人员审核。

## 2. 角色

- `PATIENT`：新建预问诊、查看记录、补充信息、查看随访任务、维护健康资料。
- `CLINICIAN`：查看待审队列，核对患者原话、事实答案、规则、覆盖状态、AI 摘要和引用，完成终审并决定是否创建随访。
- `FOLLOWUP_STAFF`：执行已激活计划产生的任务。
- `ADMIN`：查看安全告警、AI 运行、知识来源和审计记录。

## 3. 患者端需求

患者工作区包含“新建预问诊、问诊记录、随访任务、健康资料”四区。桌面端使用侧边导航，窄屏使用顶部导航。

预问诊分四阶段：

1. 哪里不舒服：中文分类、搜索、常用症状和其他不适；系统生成可编辑主诉摘要。
2. 具体情况：只问开始时间、变化过程、当前状态、活动影响和症状特异事实；每题均允许“不知道/说不清”。
3. 特别注意：集中检查胸痛、呼吸困难、真正失去意识和意识异常；命中规则时允许直接提交。
4. 检查提交：以患者语言汇总，确认“以上信息与我填写的一致”。

草稿应自动保存在本机，并支持写入服务端、保存退出和恢复。提交后不能直接修改，但可追加补充信息。

## 4. 症状与规则

服务端目录包含胸痛、呼吸困难、晕厥、意识异常、头痛、头晕、发热、咳嗽、腹痛、恶心或呕吐、腹泻、乏力、心悸、皮疹或过敏不适、肢体无力或麻木及其他不适。

确定性规则仅为：

- 意识异常事实为“是” → `EMERGENCY`
- 胸口不适事实为“是”且呼吸困难事实为“是” → `EMERGENCY`
- 胸口不适事实为“是”且真正失去意识事实为“是” → `EMERGENCY`
- 当前呼吸困难事实为“是” → `URGENT`

没有命中上述规则时不得用活动影响或其他事实换算旧数字阈值。`RECORD_ONLY` 和 `CUSTOM` 不得静默得到 `ROUTINE`。

## 5. 数据需求

- 新病例为 `INTAKE_V2`，不写数字严重度。
- `SymptomReport` 保存目录版本、支持级别、来源、事实字段和 JSONB 答案。
- `patient_profiles` 保存年龄段、必要生理信息、慢病、过敏和长期用药；每项具有无、未知、已填写状态。
- 提交时保存健康资料快照。
- `INTAKE_V1` 保留原始数字字段，只读展示，不推断新事实答案。
- `PATIENT` 替代旧患者角色，JWT、数据库约束和路由保持一致。

## 6. AI/RAG 需求

AI 请求不含数字严重度。Provider 只能整理摘要、遗漏问题和证据，不得自行改变确定性规则结果。无证据、无对应规则、引用越界和降级尝试必须阻断或明确转人工复核。知识材料来自可追溯网络来源，保存 URL、抓取时间、哈希、对象键和版本。

## 7. 非功能需求

- 390px 与桌面视口可完成核心流程。
- 键盘可操作，焦点可见，危险提示同时使用文字，动态问题使用 `aria-live`。
- PostgreSQL 为唯一业务数据库，集成测试不得使用 H2。
- 所有含身份风险的自由文本在写库前脱敏。
- `期末任务.docx` 永久排除在自动修改、转换和导出范围之外。
