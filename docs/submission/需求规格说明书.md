# 需求规格说明书

## 1. 引言
### 1.1 编写目的
本文档定义「基层医疗安全型预问诊与随访平台」的功能与非功能需求，作为设计、开发、测试与验收的依据。

### 1.2 项目背景与定位
- 课程实训项目；**教学用辅助系统**，不提供真实诊断、不替代医生；
- 技术栈：Vue 3 + Spring Boot + Python FastAPI（LangChain 理念的多 Agent 编排）+ PostgreSQL/pgvector + MinIO + Docker Compose；
- 核心特色：**医疗安全边界**（规则兜底+安全审查+人工审核）与**全链路可追溯**。

### 1.3 术语
RAG（检索增强生成）、红旗症状（提示危重风险的症状组合）、预问诊（就诊前的结构化信息采集）。

## 2. 用户角色与核心需求（用户故事）
### 2.1 患者模拟用户（PATIENT）
- US-P1：作为患者，我要注册登录并管理自己的模拟患者档案（基本资料/既往/过敏/用药），以便反复用于演示问诊。
- US-P2：作为患者，我要分步骤填写预问诊（主诉/起病/严重度/伴随/诱因/既往/过敏/用药/特殊人群/补充），能随时存草稿、再次编辑，提交后防重复。
- US-P3：作为患者，我要看到提交后的处理进度（结构化→检索→风险→安全→汇总）。
- US-P4：作为患者，当医务人员要求补充时，我要能修改并重新提交。
- US-P5：作为患者，我要在**审核通过后**查看建议（含免责声明），并查看/配合完成随访任务、填写反馈。

### 2.2 医务人员（DOCTOR）
- US-D1：作为医生，我要在待审核队列按风险等级优先处理预问诊。
- US-D2：作为医生，我要同屏对照原始信息、结构化结果、红旗规则命中、指南引用、AI 摘要与安全审查结果。
- US-D3：作为医生，我要能修改 AI 摘要/风险等级后通过，或驳回、要求患者补充。
- US-D4：作为医生，我要为已审核病例创建随访计划（频率/次数/内容项）并启动。

### 2.3 随访人员（FOLLOWUP）
- US-F1：作为随访人员，我要在任务看板按今日/逾期/高风险筛选任务。
- US-F2：作为随访人员，我要认领、执行任务并记录联系结果与症状变化；可延期、标记失联、风险升级（升级触发安全告警）。
- US-F3：作为随访人员，我要查看患者症状变化趋势图。

### 2.4 系统管理员（ADMIN）
- US-A1：管理用户/角色/权限；US-A2：管理指南与知识库（上传/启停/重建/检索测试）；US-A3：管理规则（含版本与在线测试）；US-A4：管理模型配置与 Prompt 版本；US-A5：查看 Agent 运行记录；US-A6：处理安全告警；US-A7：查询审计日志；US-A8：维护系统配置。

## 4. 非功能需求（可测量）
| 编号 | 类别 | 指标 |
|---|---|---|
| NFR-01 | 性能 | 普通查询 P95≤500ms；提交≤800ms；AI 异步 |
| NFR-02 | 并发 | 列表 20 并发无错误；AI 4 路并发不丢步骤 |
| NFR-03 | 安全 | 越权 40302；注入 100% 拦截；日志无明文敏感 |
| NFR-04 | 可用性 | AI 不可用→自动降级（Mock/人工队列），规则结果不丢 |
| NFR-05 | 可审计 | 任一 AI 结论可回溯到模型/Prompt/知识库/规则版本+引用原文 |
| NFR-06 | 部署 | docker compose 一条命令启动全部服务 |
| NFR-07 | 兼容 | Chrome/Edge 最近两版 |
| NFR-08 | 上传 | txt/md/pdf ≤10MB，MIME 校验 |

## 5. 业务闭环（验收主线）
患者填报 → 脱敏 → 结构化 → 规则预筛 → RAG 检索 → 多 Agent 风险复核 → 医生模拟审核 → 随访计划 → 自动生成任务 → 随访执行 → 记录归档；全程留引用、版本与审计。**AI 输出不得绕过人工审核直接作为正式结论。**
