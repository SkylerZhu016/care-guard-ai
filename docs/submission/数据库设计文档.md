# 数据库设计文档

> DDL 唯一来源：`backend/src/main/resources/db/migration/V1__init.sql`（Flyway 版本化管理）。

## 1. 概览
- 数据库：PostgreSQL 16 + pgvector（`CREATE EXTENSION vector`）。
- 表数量：34 张，分 8 组。命名：小写下划线；主键 `id BIGSERIAL`；时间 `created_at/updated_at timestamptz default now()`。
- ER 关系主线：`users 1─n simulated_patients 1─n visits 1─n {symptoms, visit_status_logs, symptom_extractions, rule_hits, citations, agent_runs 1─n agent_run_steps}`，`visits 1─1 triage_results`、`1─n review_records`；`knowledge_documents 1─n knowledge_chunks`；`followup_plans 1─n followup_tasks 1─n followup_records`。

## 2. 分组明细

### 2.1 认证权限（6）
| 表 | 关键字段 | 约束/索引 |
|---|---|---|
| users | username UK、password_hash、enabled、failed_attempts、locked_until | 登录锁定策略字段 |
| roles / permissions | code UK | 4 角色/权限点 |
| user_roles / role_permissions | 联合 PK | 级联删除 |
| refresh_tokens | token_hash UK、expires_at、revoked、replaced_by | 轮换吊销 |

### 2.2 患者档案（4）
| simulated_patients | patient_no UK、owner_user_id FK、chronic_tags jsonb | owner 索引（本人数据隔离） |
| patient_histories / allergy_records / medication_records | patient_id FK + 索引 | 级联删除 |

### 2.3 预问诊（5）
| visits | visit_no UK、status、risk_level、form_data jsonb、version 乐观锁 | status/patient/owner 三索引 |
| visit_status_logs | from/to/operator/reason | 流转必写 |
| symptoms / symptom_extractions / triage_results | triage_results.visit_id UK（一诊一结论） | extractions 存 schema/model/prompt 版本 |

### 2.4 规则引擎（3）
| rule_definitions | code UK、condition_expr jsonb、current_version、deleted | 软删 |
| rule_versions | (rule_id,version) UK | 改动即新版本 |
| rule_hits | visit FK、evidence 快照 | visit 索引 |

### 2.5 知识库（2）
| knowledge_documents | status(PENDING/ENABLED/DISABLED/INGEST_FAILED)、file_hash、version | 软删 |
| knowledge_chunks | (document_id,chunk_no,version) UK、embedding vector(256)、section/page_no | 向量由 ai-service 写 |

### 2.6 AI 治理（7）
| model_configs / prompt_templates / prompt_versions | (template_id,version) UK；不存 Key |
| agent_runs / agent_run_steps | status/current_step/四版本/tokens；步骤输入输出快照 |
| citations / safety_alerts | citations 落知识库版本；alerts OPEN/ACK/CLOSED |

### 2.7 审核随访（4）
| review_records | ai_snapshot jsonb（版本对比） |
| followup_plans / followup_tasks | 状态机；tasks(status,due_date) 复合索引；version 乐观锁 |
| followup_records | symptom_change 枚举（趋势图数据源） |

### 2.8 系统（3）
| uploaded_files / audit_logs / system_configs | audit 只增不改；configs 存 knowledge_version/rule_version 计数器 |

## 3. 设计要点
1. **状态字段**：VARCHAR 枚举，合法性由应用层状态机保证，流转全量写日志表。
2. **并发控制**：visits/followup_tasks 乐观锁 `version`；状态流转在事务内 `SELECT … FOR UPDATE`。
3. **事务边界**：提交问诊（visit+run+日志+审计）、审核（review+状态+日志）、任务完成（task+record）均为单事务。
4. **软删除**：文档/规则 deleted；用户 enabled。
5. **敏感字段**：phone/id_card 列表接口服务端掩码；审计/日志仅存掩码摘要。
6. **向量策略**：embedding 统一 256 维由 ai-service 写入；升级维度需新 migration + 重建。
7. **迁移与重置**：Flyway V1 建表 / V2 种子；`data-pipeline/reset_demo.*` 一键重置演示数据。
