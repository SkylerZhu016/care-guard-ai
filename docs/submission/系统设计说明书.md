# 系统设计说明书

## 1. 系统架构（架构图）

```
┌────────────────────────────────────────────────────────────────┐
│                          浏览器 (Vue 3 SPA)                     │
└──────────────────────────────┬─────────────────────────────────┘
                               │ HTTPS
┌──────────────────────────────▼─────────────────────────────────┐
│                        Nginx (80)                              │
│              静态资源托管 + /api 反向代理 + 安全头               │
└──────────┬───────────────────────────────┬─────────────────────┘
           │ /api/v1                        │ /api/internal
┌──────────▼─────────────────┐   内部REST   ┌▼────────────────────┐
│  Spring Boot 业务后端 8080  │◄────────────►│  FastAPI AI 服务 8000 │
│  认证/RBAC/状态机/规则引擎   │  X-Internal  │  结构化/检索/风险/     │
│  审核/随访/审计/文件/SSE    │   -Token     │  安全/汇总 Agent+RAG  │
└──────┬──────────────┬──────┘              └──────┬─────────────┘
       │ JPA          │ MinIO SDK                  │ SQLAlchemy
┌──────▼─────────┐  ┌─▼──────────┐                 │
│ PostgreSQL 16  │  │ MinIO 9000 │◀────────────────┘
│  + pgvector    │  │ 对象存储    │
│ 业务34表+向量表 │  └────────────┘
└────────────────┘
```

**服务职责硬边界：**
- Spring Boot：唯一的业务状态写方（visits/followup/users…）；认证授权；规则引擎；审计；SSE。
- FastAPI：大模型调用、RAG、文本结构化、安全审查；只写 AI 产物表；业务状态变更一律回调后端内部接口。

## 2. 用例图（文字描述）

- **患者模拟用户**：注册/登录 → 管理档案 → 填写分步预问诊(草稿) → 提交 → 查看进度 → (补充信息) → 查看已审核建议 → 查看随访计划 → 填写随访反馈。
- **医务人员**：登录 → 待审核队列 → 查看结构化/规则命中/引用/AI摘要/安全结果 → 修改/通过/驳回/要求补充 → 创建随访计划 → 启动/暂停/终止。
- **随访人员**：任务看板(今日/逾期/高风险) → 认领/开始 → 填写随访记录 → 延期/失联/升级 → 查看趋势。
- **管理员**：用户/角色权限/指南/知识库/规则/模型/Prompt 版本/Agent 运行记录/安全告警处理/审计日志/系统配置。

## 3. 状态机设计

### 3.1 预问诊 visits
```
DRAFT → SUBMITTED → STRUCTURING → RULE_SCREENED → AI_ANALYZING
  → PENDING_REVIEW ─┬→ REVIEWED → ARCHIVED
                    ├→ NEED_INFO ─(患者补充)→ PENDING_REVIEW
                    └→ REJECTED
任意处理中状态 ─(异常)→ FAILED ─(人工重试)→ SUBMITTED
```
非法跳转抛 40901；每次流转写 visit_status_logs。

### 3.2 AI 运行 agent_runs
`PENDING → RUNNING → COMPLETED | PARTIAL | REVIEW_FAILED | FAILED | TIMEOUT | CANCELLED`

### 3.3 随访计划 / 任务
- 计划：`DRAFT → PENDING_START → ACTIVE ⇄ PAUSED → COMPLETED | TERMINATED`
- 任务：`PENDING → ASSIGNED → IN_PROGRESS → COMPLETED | DELAYED | LOST | ESCALATED | CANCELLED`

## 4. 核心业务时序图

### 4.1 提交预问诊（核心链路）
```
患者      前端        Spring Boot          FastAPI           DB
 │ 提交     │ POST /visits │                  │                │
 │─────────►│─────────────►│ visit+run+审计    │                │
 │          │              │ 状态机→STRUCTURING │                │
 │          │              │──POST /internal/pipeline/start──►│
 │          │◄──201────────│                  │ 后台异步流水线  │
 │◄SSE连接──│◄SSE轮询DB────│◄────写steps/extractions/citations─►│
 │ 逐步进度  │              │                  │                │
 │          │              │◄──POST /internal/.../completed───│
 │          │              │ visit→PENDING_REVIEW             │
```

### 4.2 审核与随访
```
医生 → POST /reviews(APPROVE) → visit=REVIEWED+review_records(快照)
     → POST /followup-plans → start → 批量生成任务
随访 → claim → start → complete(+record) / escalate(+告警)
```

## 5. 部署图

Docker Compose 5 服务：`db(pgvector/pg16)` → `minio` → `backend(8080)` → `ai-service(8000)` → `frontend(nginx:80)`；健康检查链式 depends_on；数据卷 pgdata/miniodata；`.env` 注入密钥。

## 6. 关键技术决策（ADR）
| # | 决策 | 理由 |
|---|---|---|
| D1 | PostgreSQL+pgvector 单库 | 业务/向量一库，向量不替代业务库 |
| D2 | 简化 Redis/Celery（增强项） | 课程规模下 SSE 轮询+FastAPI 后台任务足够 |
| D3 | AI 产物直写、业务状态仅后端写 | 业务一致性与审计责任单一归属 |
| D4 | Mock LLM 降级 | 离线演示兜底、评测基线、防伪造 |
| D5 | HASH 嵌入+关键词混合检索 | 无 GPU/外网可跑通 RAG；可插拔真实嵌入 |
| D6 | 规则引擎 DB 配置 JSON DSL | 确定性安全底线、可热更新、免重型引擎 |
