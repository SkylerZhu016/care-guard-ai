# 患者问诊与随访问题报告：v2 处理结果

## 原问题

旧实现存在以下结构性风险：患者流程被固定目录和固定表单限制；统一数字评分贯穿前端、数据库、Java 规则与 Python AI；目录外症状会落入自动常规结果；患者角色与产品定位不合适；随访模板过窄。

## 已实施的修复

- 患者工作区拆为新建预问诊、问诊记录、随访任务、健康资料。
- 症状目录改为服务端版本化目录，常见症状可记录，“其他不适”支持自定义名称。
- 新问诊不再采集数字评分，改为开始时间、变化过程、当前状态、活动影响和特异事实答案。
- 确定性规则只读取明确事实，不使用任何旧数字阈值。
- 仅含 `RECORD_ONLY/CUSTOM` 时：`ruleUrgency=null`、`coverageStatus=NONE`、`assessmentStatus=REQUIRES_MANUAL_REVIEW`。
- 混合症状为 `PARTIAL`，未支持部分不能降低已命中的规则等级。
- 旧写接口返回 410；历史 `INTAKE_V1` 只读，不把旧分数推断为新答案。
- 角色迁移为 `PATIENT`；随访模板迁移为 `GENERAL_FOLLOWUP_V1`。
- AI 请求改为事实型结构，Provider 只整理摘要、遗漏问题和证据。

## 验收重点

1. 头痛、腹痛、自定义不适不得得到自动 `ROUTINE`。
2. 胸口不适伴呼吸困难、胸口不适伴真正失去意识、意识异常、单独呼吸困难保持确定性等级。
3. 患者页面不显示英文代码、规则代码、模型、覆盖枚举或数字评分。
4. 医务页面分层显示患者原话、事实答案、规则、覆盖、AI 摘要和引用。
5. 健康资料保存快照，提交后可补充而不能改写原问诊。

## 保留边界

系统整理信息而非诊断或处方；所有自动结果必须人工审核；敏感字段写库前脱敏；知识检索不能替代确定性规则依据。
