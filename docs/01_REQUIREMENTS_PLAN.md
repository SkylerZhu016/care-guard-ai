# 01 需求规划（用户故事 / 用例 / 功能与非功能需求）

## 1. 用户故事

### 患者模拟用户（PATIENT）
- US-P1 作为患者，我要注册登录，以便使用系统。
- US-P2 作为患者，我要为模拟患者建立档案（基本资料/既往史/过敏史/用药），以便问诊时自动带出。
- US-P3 作为患者，我要分步骤填写预问诊并可暂存草稿、再次编辑，以便完整描述病情。
- US-P4 作为患者，提交后我要看到处理进度，以便了解系统在工作。
- US-P5 作为患者，我要查看经医务人员审核后的建议与风险提示，并明确看到「不能替代医生诊断」。
- US-P6 作为患者，被要求补充信息时我要能修改后重新提交。
- US-P7 作为患者，我要查看随访计划并填写随访反馈。

### 医务人员（DOCTOR）
- US-D1 作为医生，我要有待审核队列，可按风险等级/时间筛选。
- US-D2 作为医生，审核时我要同屏看到：原始主诉、结构化结果、规则命中、指南引用原文、AI 摘要、安全审查结果。
- US-D3 作为医生，我要能修改 AI 摘要/风险等级后通过，或驳回、要求补充，并留审核意见。
- US-D4 作为医生，审核通过后我要能创建随访计划（频率/结束条件/随访项）。

### 随访人员（FOLLOWUP）
- US-F1 作为随访员，我要任务看板（今日/逾期/高风险）并能认领任务。
- US-F2 作为随访员，我要记录联系结果与症状变化，可标记完成/延期/失联/升级。
- US-F3 作为随访员，我要查看患者症状变化趋势图。

### 管理员（ADMIN）
- US-A1 管理用户/角色/权限（启停、重置密码）。
- US-A2 管理指南与知识库（上传/启停/重建索引/查看分块）。
- US-A3 管理规则（增改/启停/版本/在线测试）。
- US-A4 管理模型与 Prompt 版本；查看 Agent 运行记录（步骤/token/耗时/四版本）。
- US-A5 处理安全告警；查询审计日志；系统配置。

## 2. 用例规约（关键用例）

| 用例 | 主 actor | 前置 | 主流程 | 异常流 |
|---|---|---|---|---|
| UC-01 提交预问诊 | PATIENT | 已登录且有档案 | 分步填写→提交→状态 SUBMITTED→AI 流水线→PENDING_REVIEW | 重复提交→幂等返回；AI 失败→FAILED 可重试；缺必填→40002 |
| UC-02 规则预筛 | 系统 | UC-01 | 组装规则上下文→逐条求值→写 rule_hits→计算最高风险 | 规则异常→跳过该条并告警，不中断 |
| UC-03 多Agent分析 | 系统 | UC-01 | STRUCTURE→RETRIEVE→RISK→SAFETY→SUMMARY 逐步落库 | 任一步失败→PARTIAL/FAILED 降级，保留规则结果 |
| UC-04 医务审核 | DOCTOR | visit=PENDING_REVIEW | 队列→详情对照→修改→APPROVE/REJECT/REQUEST_INFO | 状态已被他人处理→40901 |
| UC-05 随访闭环 | FOLLOWUP | 计划 ACTIVE | 任务看板→认领→执行→complete 写 record | 逾期自动 DELAYED；升级→告警 |
| UC-06 知识摄取 | ADMIN | 已登录 | 上传文档→MinIO→AI 摄取→ENABLED | 解析失败→INGEST_FAILED 可重传 |

## 3. 功能需求清单（FR）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-01 | 注册/登录/刷新/登出/改密；失败 5 次锁 15 分钟 | 必 |
| FR-02 | RBAC 四角色 + 接口级权限 + 患者本人数据隔离 | 必 |
| FR-03 | 患者档案 CRUD + 既往/过敏/用药子记录 | 必 |
| FR-04 | 分步表单 11 步 + 草稿 + 防重复提交 + 校验 | 必 |
| FR-05 | 问诊状态机 11 态 + 流转日志 + 非法跳转拒绝 | 必 |
| FR-06 | 症状结构化（JSON Schema+置信度+缺失项） | 必 |
| FR-07 | 规则引擎（6 类规则/优先级/版本/启停/命中记录/在线测试） | 必 |
| FR-08 | 知识库（上传/解析/分块/嵌入/检索/启停/版本/重建） | 必 |
| FR-09 | 引用可追溯（文档/章节/页码/片段/得分） | 必 |
| FR-10 | 五段多 Agent + 安全审查 + SSE 进度 + 降级 | 必 |
| FR-11 | 审核工作台（队列/对照/修改/三动作/意见/历史对比） | 必 |
| FR-12 | 随访计划+任务自动生成+看板+四态操作+趋势图 | 必 |
| FR-13 | 安全告警（9 类）+处理流 | 必 |
| FR-14 | 审计日志（操作人/动作/对象/前后摘要/IP/traceId/四版本） | 必 |
| FR-15 | 模型/Prompt 版本管理页 | 必 |
| FR-16 | Docker Compose 一键启动 + Mock 离线演示 | 必 |
| FR-17 | 数据漂移监控/短信邮件提醒 | 增强 |

## 4. 非功能需求（NFR，课程级可测量）

| 编号 | 指标 | 目标值 |
|---|---|---|
| NFR-01 | 普通查询接口响应 | P95 ≤ 500ms（本地 4C8G） |
| NFR-02 | 预问诊提交接口 | ≤ 800ms（不含 AI 异步段） |
| NFR-03 | AI 流水线 | 异步执行，Mock 模式 ≤ 8s 全链路 |
| NFR-04 | 文件上传 | ≤ 10MB，仅 txt/md/pdf，MIME+魔数校验 |
| NFR-05 | 并发 | 20 并发普通查询无错误；AI 并发限 4 |
| NFR-06 | 可用性 | 单容器重启后自动恢复；演示可离线 |
| NFR-07 | 安全 | 密钥仅环境变量；日志无明文敏感字段；XSS/SQLi 防护 |
| NFR-08 | 审计保留 | 审计日志保留 ≥ 180 天（演示期全量） |
| NFR-09 | 兼容 | Chrome/Edge 最近两版 |
| NFR-10 | 可维护 | 统一错误体+traceId；三层测试可运行 |

## 5. 需求边界（明确不做）
真实 HIS 对接、真实患者数据、在线处方、确定性诊断输出、支付、IM、移动端原生 App、多租户计费。
