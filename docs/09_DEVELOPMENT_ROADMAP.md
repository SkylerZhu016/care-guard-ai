## 2. Git 协作
- 分支：`main`（保护，仅 PR 合入）；`feature/<域>-<名>`；`fix/<名>`；里程碑打 tag（v0.1-MVP…v1.0）。
- Commit：约定式 `feat(backend): 提交预问诊幂等` / `fix(ai): json修复重试`。
- PR 模板：变更说明/影响接口/测试证据(截图或命令输出)/关联 Issue；≥1 人评审；CI（如有）绿。
- Issue 模板：Bug（复现步骤/期望/实际/环境）、Feature（用户故事/验收标准）。
- 合并顺序纪律：migration → backend → ai-service → frontend → deploy；接口变更先改 04 文档。
- 冲突规避：按目录认领模块；共享文件（路由表/类型文件）先沟通再改。

## 3. 里程碑
M1(P1 末) 登录骨架；M2(P3 末) 无 AI 的业务主干；M3(P5 末) AI 闭环；M4(P7 末) 全业务闭环=MVP；M5(P9 末) 交付。

## 4. 人员分工（5 角色，可伸缩 3~6 人）
| 角色 | 负责 |
|---|---|
| FE | frontend 全部页面与联调 |
| BE | backend 模块、规则引擎、SSE、审计 |
| AI | ai-service、RAG、Mock、评测 |
| DB/Ops | 迁移、种子、compose、脚本、备份 |
| QA/Docs | 测试计划执行、提交材料、演示脚本 |
接口对齐会：每阶段末 30 分钟；联调窗口：P5/P7/P9 各一次集中联调。
