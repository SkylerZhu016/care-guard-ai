# 项目完成复核（v2 重构）

## 当前实现

- PostgreSQL V4：患者角色、v2 问诊字段、资料快照、补充信息、覆盖状态和可空规则等级。
- Java：版本化目录、患者资料、v2 草稿/提交/历史读取/医务队列、事实型规则、v1 写接口 410。
- Python：请求模型无数字评分，Fake 与真实 Provider 不进行阈值升级，规则等级为空时保持为空。
- Vue：患者四区、四阶段动态问诊、其他不适、未知选项、即时重点提示、本机草稿恢复、健康资料和补充信息；医务端分层审核。
- 文档：README、SRS、开发指导书、OpenAPI、架构、ER、时序、RAG、问题报告和演示流程已同步。

## 安全结论

- 未支持症状不会自动得到常规或无风险结论。
- 规则只保留四条有现有依据的事实逻辑。
- AI 不得改变规则覆盖资格或自动创建确定性等级。
- 患者端不展示内部代码和治理信息。
- `期末任务.docx` 未修改、未转换、未重导出。

## 历史兼容

V1–V3 Flyway 文件为已发布历史迁移，保留原文以维持校验。V4 在数据库中完成角色和字段迁移。旧数字字段只以 `legacy_severity` 读取，新病例保持为空。

## 待持续改进

当前 64 维 hashing embedding 只验证工程链路，不代表医学语义质量；网络知识覆盖增加不代表临床有效性。任何扩展自动规则都必须先取得依据、评审和回归测试。
